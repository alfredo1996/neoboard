# design-sync notes — @neoboard/components

Storybook shape. Synced from the `component/` workspace package. First sync: 2026-06-24.

## Toolchain / install

- Repo pins **node 20** (`.nvmrc`); the machine default is node 24. Build/storybook/converter all run under node 20 (`nvm use 20`).
- Package manager: **npm** (`package-lock.json`). `npm ci` FAILS — the lockfile omits the private optional `@neoboard/enterprise` package (`Missing: @neoboard/enterprise from lock file`). The existing hoisted `node_modules` is complete and was used as-is. Do NOT `npm ci`; if deps are missing, `npm install` (will touch the lockfile) or restore node_modules.

## Why the entry is SOURCE, not dist (critical)

- `@neoboard/components` ships **raw TS** (`main: ./src/index.ts`); there is no published dist or `.d.ts`. The vite lib build (`vite build`) uses **rolldown**, which — when react is `external` — converts CJS deps' `require("react")` (Radix `react-primitive`, `prop-types`, `react-is`, `react-grid-layout`/`react-resizable`) into rolldown's own **dynamic `__require("react")`** that throws _"Dynamic require of react is not supported"_ at runtime. Because the bundle is one IIFE, that throw means `window.NeoBoard` never initializes → **every preview renders blank**.
- Fix: bundle from **source** (`cfg.entry: component/src/index.slim.ts`). The converter's own esbuild `reactShim` intercepts every `require("react")`/`import "react"` → `window.React`, so no dynamic require survives. Verified: `0` dynamic `require("react")` calls in `_ds_bundle.js`, components render.
- `cfg.tsconfig: tsconfig.dssync.json` (path is **relative to the package dir**, i.e. `component/` — `cfgPath` resolves against `PKG_DIR`, NOT repo root; a repo-root-relative value silently "not found — skipped"). It maps `@/* → ./src/*` and `@/lib/code-highlighter → ./src/lib/code-highlighter.stub.ts`.

## `.d.ts` generation (export discovery)

- The converter discovers components from the `.d.ts` export set; the entry it resolves is `<pkgDir>/index.d.ts` and it globs `component/**/*.d.ts`. The package emits no declarations (`tsconfig.json` has `noEmit:true`).
- We generate them: `component/tsconfig.dts.json` (emitDeclarationOnly → `component/.ds-types/`) + a `component/index.d.ts` re-exporting `./.ds-types/index`. tsc exits 1 (a `process` global type error from `types:[]`) but **still emits all declarations** — that exit code is expected/ignored. `buildCmd` wraps it in `|| true`.
- All of `.ds-types/`, `index.d.ts`, `tsconfig.dts.json` are gitignored (regenerated by `buildCmd`).

## Previews reference the shipped bundle — story-imports fork

- NeoBoard source files are kebab-case (`bar-chart.tsx`) but exports are PascalCase (`BarChart`). The stock `story-imports.mjs` `exportedComponentFor` matches filename≈export, so it never recognized these as components → previews **re-bundled source** (1.8 MB each, pulled CJS Radix that broke). Forked to `.design-sync/overrides/story-imports.mjs` (declared in `cfg.libOverrides`) to map kebab→Pascal. Now previews shim component imports to `window.NeoBoard` (the shipped bundle designs actually use) — tiny (~8 KB) and true-fidelity.
- Trade-off the fork surfaces: a story importing a name **not** on the public bundle fails (Element type invalid). Handled per-case below.

## CSS — must append the compiled Tailwind (critical)

- Source bundling means esbuild only emits the CSS that component source imports (just dashboard-grid's react-grid-layout css, ~4 KB) — **no Tailwind utilities**. The `[CSS_FROM_STORYBOOK]` scrape only fires when `_ds_bundle.css` is _missing_, so it didn't kick in → everything rendered unstyled (serif, no borders).
- Fix: `cfg.cssEntry: ".ds-tailwind.css"` (package-relative) — the converter **appends** it to `_ds_bundle.css`. The file is the storybook build's compiled `iframe-*.css` (Tailwind + tokens + `@font-face`), **copied** to `component/.ds-tailwind.css` (cssEntry is bounded to the package dir, so it can't point at `.design-sync/sb-reference/`). Gitignored; **regenerate on re-sync**: `cp "$(ls .design-sync/sb-reference/assets/iframe-*.css|head -1)" component/.ds-tailwind.css` (filename hash changes per storybook build).

## 5 MB upload cap — excluded components

The full library is ~11.5 MB (echarts + NVL + leaflet + cypher-lang + shiki + world.geo). Cap is **5 MB per file**. User decision (2026-06-24): exclude the heaviest from the live bundle.

- Excluded via **slim barrels**: `src/charts/index.slim.ts` (drops GraphChart→NVL, MapChart→Leaflet, ChoroplethChart→world.geo, **CirclePackingChart**), `src/components/composed/index.slim.ts` (drops QueryEditor→cypher-lang). `src/index.slim.ts` is the slim entry.
- **CirclePackingChart added to exclusions (5th)** — NOT for size: its d3-hierarchy `pack()` layout throws `extendBasis` "Uncaught Error" when bundled by esbuild (works in vite/storybook, not esbuild). Real esbuild incompatibility; broken in `window.NeoBoard` regardless of preview approach → excluded → floor card.
- The slim barrels are generated by **perl whole-statement removal** (line-based `grep -v` breaks multi-line `export type {…} from "./x"` blocks).
- **Shiki** (~1.5 MB) dropped via `code-highlighter.stub.ts` tsconfig-paths mapping. MarkdownWidget stays live, code fences unhighlighted.
- **DashboardGrid KEPT** (react-grid-layout ~200 KB; works via source-bundling+reactShim).
- Excluded components get `.d.ts`/`.prompt.md` contracts + floor cards via `cfg.overrides.<Name>.skip` (all story ids) — skipping their stories yields a clean floor card and a clean compare gate (no undefined-component errors).

## Per-component overrides (cfg.overrides / storyImports)

- **Slider**: `skip` all 5 stories — they are **sb-error** ("no storybook root content"): the storybook reference itself doesn't render Slider statically, so there's nothing to compare against. Slider IS live in `window.NeoBoard` but becomes a floor card here. (Worth revisiting: why does storybook not render Slider?)
- **Card / AppShell**: both import `CardKpi` from `@/components/ui/card`, but the ui barrel (`components/ui/index.ts`) does NOT export `CardKpi` → it's not on the public bundle. The fork made the whole `card` import shim to the global → `CardKpi` undefined → module "(page)" error. Fix: `cfg.storyImports.bundle: ["/ui/card"]` bundles the card source so `CardKpi` resolves. NOTE: Card previews then show `CardKpi`, which is NOT in the public API — designs can't actually use `CardKpi` (barrel omission, likely a NeoBoard oversight; not fixed here to avoid changing the package's public API).

## Fonts / CSS

- `cfg.extraFonts: ["design-tokens.css"]` (package-relative) ships Geist Sans + Inter `@font-face` woff2 from `component/fonts/`.
- CSS is scraped from the storybook build (`[CSS_FROM_STORYBOOK]`) — the catch-all (tailwind output + tokens). `_ds_bundle.css` also gets dashboard-grid's react-grid-layout CSS via source bundling.

## Storybook reference

- Built with `npx storybook build -c component/.storybook -o .design-sync/sb-reference` (414 entries → 77 storied components). `WidgetEditorPrototype` has no matching export → dropped (internal prototype). Result: 76 components.
- The `.storybook/preview.ts` decorator only toggles a `.dark` class (no React provider). Its bundle "fails with 2 errors" (CSS `@tailwind` import) but this is **non-blocking** — previews render in light mode by default, which is what we want. No `cfg.provider` needed.

## Re-sync risks (watch-list)

- **Slim barrels can drift from upstream.** If `src/charts/index.ts` or `src/components/composed/index.ts` gain/lose exports, the `*.slim.ts` copies won't update automatically — regenerate them with the perl one-liners (see git history / this file). A new heavy chart added upstream would bloat the bundle past 5 MB without a barrel update.
- **`code-highlighter.stub.ts`** must keep matching the real module's export surface (`highlightSync`, `ensureHighlighter`, `SUPPORTED_LANGS`). If MarkdownWidget starts importing more from it, the stub needs those too or MarkdownWidget breaks.
- **5 MB headroom**: current bundle ~3.5 MB. Adding live components/deps could exceed the cap — re-check `find ds-bundle -size +5M` after any scope change.
- The slim-build scaffolding (`src/index.slim.ts`, `src/charts/index.slim.ts`, `src/components/composed/index.slim.ts`, `src/lib/code-highlighter.stub.ts`, `tsconfig.dts.json`, `tsconfig.dssync.json`, `component/index.d.ts`) lives in the package and is currently **gitignored**. For re-sync on a fresh clone these must be regenerated — see "Re-sync regeneration" below. (Decide at commit time whether to commit them instead — regeneration via the perl one-liners is fragile.)
- **Grading provenance (first sync, 2026-06-24):** subagent fan-out was unavailable (API 529 + org policy block), so grading was done solo. The 10 chart types + Button + Card were deep-verified (full sheets); the other ~58 components were reviewed via batched montages (6/image) — gross issues (blank/unstyled/wrong content) would show, but subtle per-story deltas could be missed. All graded match except 4 close (Sankey×3 reference-empty, MarkdownWidget code-fence). A re-sync with working subagents could re-verify the montage-graded set more granularly. Post-upload, skim the live cards in claude.ai/design — re-uploads are cheap.

## Re-sync regeneration (fresh clone)

1. `nvm use 20`
2. Regenerate slim scaffolding (barrels via perl, stub, slim index, tsconfigs, index.d.ts) — or commit them.
3. `buildCmd`: `cd component && (npx tsc -p tsconfig.dts.json || true)` (emits `.ds-types/` + needs `component/index.d.ts`).
4. Rebuild `.design-sync/sb-reference` (storybook).
5. Run converter with `--entry ./component/src/index.slim.ts`.
