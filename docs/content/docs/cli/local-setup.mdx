---
title: Local Setup
description: Run NeoBoard locally with your own PostgreSQL and Neo4j.
---

Local mode runs the Next.js app directly on your machine with Node.js. Use this when you have existing databases, cannot run Docker, or want a production-like setup.

## When to Use Local Mode

- You already have PostgreSQL and Neo4j running
- Docker is unavailable or restricted in your environment
- You want hot-reload during development
- You need a setup closer to production

## Prerequisites

- **Node.js 20+**
- **PostgreSQL 14+** -- running and accessible
- **Neo4j 5+** -- running and accessible
- **Git**

## Steps

### 1. Initialize the project

```bash
git clone https://github.com/alfredo1996/neoboard.git
cd neoboard
npm run cli:build
node cli/dist/index.js init --mode local
```

This installs dependencies across all packages (`app/`, `component/`, `connection/`) and generates `app/.env.local` with fresh secrets.

### 2. Configure your database connection

Edit `app/.env.local` and set `DATABASE_URL` to point at your PostgreSQL instance:

```bash
DATABASE_URL=postgresql://neoboard:neoboard@localhost:5432/neoboard
```

### 3. Customize ports and credentials

Edit `neoboard.config.json` at the project root, or use the CLI:

```bash
node cli/dist/index.js config set ports.postgres 5433
node cli/dist/index.js config set postgres.user myuser
node cli/dist/index.js config set postgres.password mypassword
```

### 4. Start your databases

Make sure PostgreSQL and Neo4j are running and reachable on the configured ports. The CLI will check connectivity during startup.

### 5. Start NeoBoard

```bash
node cli/dist/index.js start
```

This verifies database health, runs migrations, and prints the service URLs. If a database is unreachable, you will see a warning with the expected host and port.

### 6. Start the dev server

```bash
node cli/dist/index.js dev
```

This launches the Next.js dev server with hot reload. If databases are not running, it will attempt to start them via Docker Compose as a fallback.

Open [http://localhost:3000](http://localhost:3000) to access NeoBoard.

## Environment Variables

The `app/.env.local` file is generated by `neoboard init --mode local`. These are the required variables:

| Variable | Description | Example |
|----------|-------------|---------|
| `DATABASE_URL` | PostgreSQL connection string | `postgresql://neoboard:neoboard@localhost:5432/neoboard` |
| `ENCRYPTION_KEY` | AES-256-GCM key for connector credentials (64 hex chars) | Auto-generated |
| `NEXTAUTH_SECRET` | Auth.js session signing secret | Auto-generated |
| `NEXTAUTH_URL` | Base URL of the app | `http://localhost:3000` |
| `ADMIN_BOOTSTRAP_TOKEN` | One-time token for first admin signup | Auto-generated |

To regenerate all secrets:

```bash
node cli/dist/index.js env --regenerate
```

To check that all required variables are set:

```bash
node cli/dist/index.js env --validate
```

## Config Keys

All keys available in `neoboard.config.json`:

| Key | Default | Description |
|-----|---------|-------------|
| `ports.app` | `3000` | App server port |
| `ports.postgres` | `5432` | PostgreSQL port |
| `ports.neo4j_http` | `7474` | Neo4j HTTP/Browser port |
| `ports.neo4j_bolt` | `7687` | Neo4j Bolt protocol port |
| `postgres.user` | `neoboard` | PostgreSQL username |
| `postgres.password` | `neoboard` | PostgreSQL password |
| `postgres.database` | `neoboard` | PostgreSQL database name |
| `neo4j.user` | `neo4j` | Neo4j username |
| `neo4j.password` | `neoboard123` | Neo4j password |
| `seed.script` | `scripts/seed-demo.mjs` | PostgreSQL seed script path |
| `seed.neo4j_cypher` | `docker/neo4j/init.cypher` | Neo4j seed Cypher file path |

## First-Time Signup

After starting the app, navigate to `/signup`. You will need the `ADMIN_BOOTSTRAP_TOKEN` printed during `init`. The first user gets the **admin** role automatically.
