## Overview

The Graph widget renders **graph values** — nodes, relationships and paths — as an interactive force-directed graph. Users can drag nodes, zoom, and click to explore properties.

What matters is the shape a query returns, not where it came from: the widget reads the type tag every connector puts on a graph value, so a cell that merely looks like a node (a JSON column holding `labels` and `properties`) is left as data. A connector that cannot return graph values does not offer this widget.

## Query Format

Return nodes, relationships, or paths -- not tabular data. The transform automatically extracts graph structures from the query result.

### Cypher

```cypher
MATCH (a:Person)-[r:ACTED_IN]->(m:Movie)
RETURN a, r, m
LIMIT 50
```

Paths also work:

```cypher
MATCH p = shortestPath((a:Person {name: 'Tom Hanks'})-[*]-(b:Person {name: 'Kevin Bacon'}))
RETURN p
```

### SQL

A query that returns rows of scalars has no graph in it, so the widget reports that rather than drawing an empty canvas. Use a connection whose queries can return nodes, relationships or paths.

## Options

| Option                   | Type    | Default | Description                                                                                     |
| ------------------------ | ------- | ------- | ----------------------------------------------------------------------------------------------- |
| Layout                   | select  | force   | Node positioning algorithm: Force (physics simulation), Circular (ring), or Hierarchical (tree) |
| Show Labels              | boolean | true    | Show the node label (first string property) on each node                                        |
| Show Relationship Labels | boolean | true    | Show the relationship type name on each edge                                                    |

## Virtual (synthetic) nodes

Nodes built by the query rather than read from the database -- APOC's
`apoc.create.vNode` and `apoc.create.vRelationship` -- render normally and
connect to real nodes as expected. They carry an italic `virtual` line in their
caption, and their context menu offers no **Expand**: a virtual node exists only
inside this result, so there are no neighbours in the database to fetch. To
explore outward, expand the real node it was derived from instead.

Detection is by convention, not by a flag: APOC gives virtual entities negative
ids so they cannot collide with stored ones, and the Bolt driver returns them as
ordinary nodes with no marker of their own. Anything whose id is a negative
integer is therefore treated as virtual. A connector that emitted
graph-shaped rows with genuinely negative ids would be mislabelled the same way;
none of the shipped connectors do.

## Tips

- Add a `LIMIT` to your query to keep the graph readable -- more than 200 nodes can get cluttered.
- Use the Hierarchical layout for tree-like data (org charts, category hierarchies).
