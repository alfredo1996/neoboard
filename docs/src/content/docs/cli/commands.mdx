All commands are run from the repository root as `node cli/dist/index.js <command>`. If you have the CLI installed globally, replace with `neoboard <command>`.

## setup

Full setup in one command: runs `init`, then `start` (which includes migrations).

```bash
neoboard setup [--mode <docker|local>]
```

| Option | Default | Description |
|--------|---------|-------------|
| `--mode <mode>` | `docker` | `docker` -- everything in containers. `local` -- app locally, databases separate. |

```bash
# Docker setup (default)
neoboard setup

# Local setup
neoboard setup --mode local
```

## init

Initialize project configuration and install dependencies. Creates `neoboard.config.json` and `.neoboard.local`. In local mode, also installs npm dependencies and generates `app/.env.local`.

```bash
neoboard init [--mode <docker|local>]
```

| Option | Default | Description |
|--------|---------|-------------|
| `--mode <mode>` | `docker` | `docker` or `local`. |

```bash
neoboard init --mode local
```

## start

Start NeoBoard services and run database migrations. In Docker mode, starts the PostgreSQL and Neo4j containers via `docker compose`; add `--full` to also start the app container (`setup` and `demo` do this for you). In local mode, connects to your running PostgreSQL and Neo4j instances.

```bash
neoboard start [--full] [--expose-host]
```

| Option | Default | Description |
|--------|---------|-------------|
| `--full` | `false` | Docker mode: also start the app container, and wait for it to be healthy. Without it, only the databases start. |
| `--expose-host` | `false` | Docker mode with `--full` only: let the app container reach databases running on this machine (maps `host.docker.internal`; connect with `host.docker.internal` instead of `localhost`). Rejected without `--full` or in local mode. |

The mode is read from `.neoboard.local` (set during `init` or `setup`).

```bash
neoboard start
```

## stop

Stop Docker containers. Only applies to Docker mode.

```bash
neoboard stop [--volumes]
```

| Option | Default | Description |
|--------|---------|-------------|
| `--volumes` | `false` | Also remove data volumes, giving you a clean slate. |

```bash
# Stop but keep data
neoboard stop

# Stop and delete all data
neoboard stop --volumes
```

## dev

Start the Next.js dev server with hot reload. Only works in local mode. If databases are not running, attempts to start them via Docker Compose automatically.

```bash
neoboard dev
```

No options. Validates that `app/.env.local` has all required variables before starting. Press `Ctrl+C` to stop.

```bash
neoboard dev
```

## status

Show the health of PostgreSQL, Neo4j, and the NeoBoard app. Displays mode, version, container count, and the migrations bundled with this install. The `Migrations:` line counts the entries in the local migration journal (`app/drizzle/migrations/meta/_journal.json`). It does not query the database, so it can say "N applied" against an empty or out-of-date schema. When there is no checkout, as with a standalone `npx` install, it prints `no journal found`. To see what the database has actually applied, open `/api/health` while signed in as an admin and read `data.migrations` (`applied`, `expected`, `upToDate`).

```bash
neoboard status
```

```bash
neoboard status
# Mode:        docker
# Version:     1.0.0
# Docker:      running (3 containers)
#
# Service      Status
# ---
# PostgreSQL   healthy (localhost:5432)
# Neo4j        healthy (localhost:7687)
# App          healthy (http://localhost:3000)
#
# Migrations:  12 applied (latest: 0012_add_sharing)   (journal count, not database state)
```

## doctor

Check that all prerequisites are met: Docker daemon, Docker Compose v2, Node.js version, port availability, `node_modules`, `.env.local`, and whether `ENCRYPTION_KEY` decrypts the stored credentials. Exits with code 1 if any check fails, in either mode. Checks that can fail: Docker daemon, Docker Compose v2 (Docker mode only; in local mode they are downgraded to warnings), Node.js below 20, and an `ENCRYPTION_KEY` that cannot decrypt a stored credential. Busy ports, a missing `node_modules` and a missing `.env.local` are warnings only. The decryption check is skipped when there are no stored credentials yet, or when the key or database is unavailable.

```bash
neoboard doctor
```

```bash
neoboard doctor
```

## demo

Set up a full demo environment with sample data. Runs `setup`, then seeds Neo4j with the movie graph (skipped if the graph already has nodes) and PostgreSQL with demo `creator` and `reader` users (plus an `admin` user if the database has no users yet), four demo connections, the `neoboard_demo_public` e-commerce schema and the showcase dashboards.

```bash
neoboard demo [--mode <docker|local>]
```

| Option | Default | Description |
|--------|---------|-------------|
| `--mode <mode>` | `docker` | `docker` or `local`. |

```bash
neoboard demo
# ...setup output...
# Demo environment ready!
#
# Login credentials:
#   admin:    admin@neoboard.local / admin123
#   creator:  creator@neoboard.local / creator123
#   reader:   reader@neoboard.local / reader123 (read-only)
```

## env

Generate or validate the `app/.env.local` file. In Docker mode, environment is managed by `docker-compose` so this command is not needed.

```bash
neoboard env [--regenerate] [--validate]
```

| Option | Default | Description |
|--------|---------|-------------|
| `--regenerate` | `false` | Overwrite existing `.env.local` with fresh secrets. |
| `--validate` | `false` | Check that `app/.env.local` sets all required variables (`DATABASE_URL`, `ENCRYPTION_KEY`, `NEXTAUTH_SECRET`, `NEXTAUTH_URL`, `API_KEY_HMAC_SECRET`) to non-empty values. Their format is not checked. Local mode only. |

```bash
# Generate .env.local (skips if it already exists)
neoboard env

# Force regenerate all secrets
neoboard env --regenerate

# Validate existing file
neoboard env --validate
```

## config get

Get a single configuration value by key.

```bash
neoboard config get <key>
```

Valid keys: `ports.app`, `ports.postgres`, `ports.neo4j_http`, `ports.neo4j_bolt`, `postgres.user`, `postgres.password`, `postgres.database`, `neo4j.user`, `neo4j.password`, `seed.script`, `seed.neo4j_cypher`.

```bash
neoboard config get ports.app
# 3000
```

## config set

Set a configuration value. Port values are automatically parsed as numbers.

```bash
neoboard config set <key> <value>
```

```bash
neoboard config set ports.app 4000
neoboard config set postgres.database mydb
```

## plugin add

Install an external chart or connector plugin from npm, validate it, and register it in the appropriate manifest. The CLI auto-detects whether the package is a chart plugin (has `transform`) or connector plugin (has `createModule`).

```bash
neoboard plugin add <package> [--override] [--export <name>]
```

| Option | Default | Description |
|--------|---------|-------------|
| `--override` | `false` | Allow replacing a built-in plugin of the same type. |
| `--export <name>` | `default` | Named export to use from the package. |

The CLI validates the package after installation:
- Must export an object with `type` (string) and `label` (string)
- Chart plugins must have `transform` (function) and `compatibleWith` (array)
- Connector plugins must have `createModule` (function) and `category` (enum)
- If validation fails, the package is automatically uninstalled

```bash
# Add a connector plugin
neoboard plugin add @myorg/neoboard-mongodb
# ✔ Installed @myorg/neoboard-mongodb
# ✔ Plugin "mongodb" registered as connector in neoboard-connectors.json

# Add a chart plugin that overrides a built-in
neoboard plugin add @myorg/custom-bar --override
# ✔ Plugin "bar" registered as chart in neoboard-plugins.json

# Invalid package — auto-rollback
neoboard plugin add some-random-package
# ✔ Installed some-random-package
# ERROR: Package "some-random-package" is not a valid NeoBoard plugin:
#   - "type" must be a non-empty string
#   - Not a valid NeoBoard plugin
# WARN: Rolling back: uninstalling some-random-package
```

## plugin remove

Unregister an external plugin and uninstall its npm package. Cannot remove built-in plugins.

```bash
neoboard plugin remove <package>
```

```bash
neoboard plugin remove @myorg/neoboard-mongodb
# ✔ Plugin "@myorg/neoboard-mongodb" removed

# Attempting to remove a built-in
neoboard plugin remove neo4j
# ERROR: Package "neo4j" is not registered as an external plugin.
#        Cannot remove built-in plugins.
```

## logs

Tail the database container logs. Available services: `postgres` (or `pg`) and `neo4j`. This command reads the databases-only compose file, so it does not show the app container started by `setup --full`, `demo` or `start --full`. For that container, use `docker logs -f neoboard-app`.

```bash
neoboard logs [service] [-f] [-n <lines>]
```

| Option | Default | Description |
|--------|---------|-------------|
| `[service]` | all | `postgres`, `pg` or `neo4j`. Omit for both databases. |
| `-f, --follow` | `false` | Follow log output in real time. |
| `-n, --lines <n>` | `50` | Number of lines to show. |

```bash
# Last 50 lines from PostgreSQL and Neo4j
neoboard logs

# Follow PostgreSQL logs
neoboard logs postgres -f

# Last 100 lines from Neo4j
neoboard logs neo4j -n 100
```

## db migrate

Run Drizzle database migrations. `--status` and `--dry-run` only read the migration journal shipped with NeoBoard; they do not contact the database.

```bash
neoboard db migrate [--status] [--to <version>] [--dry-run]
```

| Option | Default | Description |
|--------|---------|-------------|
| `--status` | `false` | List the migrations shipped in the journal and when each was generated (does not read the database, so it cannot tell which are applied). |
| `--to <version>` | latest | Target migration version (not yet fully supported). |
| `--dry-run` | `false` | List every migration in the journal without applying anything (does not check which are pending). |

```bash
# Apply all pending migrations
neoboard db migrate

# List the migrations shipped with this version
neoboard db migrate --status

# List migrations without applying any
neoboard db migrate --dry-run
```

## db seed

Seed databases with sample data. Seeds both Neo4j and PostgreSQL by default.

```bash
neoboard db seed [--neo4j] [--demo]
```

| Option | Default | Description |
|--------|---------|-------------|
| `--neo4j` | `false` | Seed only Neo4j graph data. |
| `--demo` | `false` | Seed only PostgreSQL demo user and dashboards. |

If Neo4j already has nodes, the Neo4j seed is skipped automatically.

```bash
# Seed everything
neoboard db seed

# Seed only Neo4j
neoboard db seed --neo4j

# Seed only demo user/dashboards
neoboard db seed --demo
```

## db reset

Drop and recreate the PostgreSQL database, replay all migrations, and optionally re-seed. Only works on localhost databases as a safety measure.

```bash
neoboard db reset [--no-seed] [--force]
```

| Option | Default | Description |
|--------|---------|-------------|
| `--no-seed` | `false` | Skip seeding after reset. |
| `--force` | `false` | Skip the confirmation prompt. |

```bash
# Reset with confirmation prompt
neoboard db reset

# Reset without prompting, skip seed
neoboard db reset --force --no-seed
```

## db dump

Export the PostgreSQL database to a SQL file. Useful for backups before migrations or resets.

```bash
neoboard db dump [--output <path>] [--data-only]
```

| Option | Default | Description |
|--------|---------|-------------|
| `--output <path>` | `neoboard-dump-<timestamp>.sql` | Output file path. |
| `--data-only` | `false` | Dump data only, no schema definitions. |

```bash
# Dump to default file
neoboard db dump

# Dump to specific file
neoboard db dump --output backup.sql

# Dump data only
neoboard db dump --data-only
```

## db restore

Restore a dump taken with `neoboard db dump` or `pg_dump`. Accepts both plain
SQL and custom-format (`pg_dump -Fc`) archives — the format is detected from the
file, not its extension.

```bash
neoboard db restore <file> [--clean] [--force]
```

| Option | Default | Description |
|--------|---------|-------------|
| `--clean` | `false` | Drop the existing objects first. Required when the target database is not empty. |
| `--force` | `false` | Skip the confirmation prompt and the running-app check. |

Before restoring, the command checks the things that otherwise fail late and
confusingly:

- **The database must be reachable.** It refuses rather than reporting an empty
  target it could not actually read.
- **A non-empty target needs `--clean`.** Without it the restore collides
  partway through with duplicate-key errors; the command names the tables it
  found instead.
- **NeoBoard must not be running.** The app image boots with
  `MIGRATE_ON_START=1`, so a live instance recreates the schema underneath the
  restore and holds connections that block dropping the database.

Afterwards it prints the row count of every restored table, and verifies that
the configured `ENCRYPTION_KEY` can actually decrypt the restored credentials —
a mismatch there exits non-zero, because the data is back but every connector is
unusable.

```bash
# Restore into a fresh database
neoboard db restore neoboard-dump-2026-07-20T09-30-00.sql

# Replace the contents of an existing database
neoboard db restore backup.sql --clean

# Unattended (no prompt, no running-app check)
neoboard db restore backup.dump --clean --force
```

:::caution[`--clean` is destructive by design]
It drops what is in the target before restoring. Take a fresh `neoboard db dump`
of the current state first if there is any doubt about which backup you have.
:::
