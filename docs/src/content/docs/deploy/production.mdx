Docker Compose is the **recommended** way to run NeoBoard in production; the [install](/start-here/install) paths set up a development stack. Prefer a plain Node.js process, systemd, or Kubernetes? [Run from a build](/deploy/run-from-a-build) covers those — same app, same variables. Otherwise use the dedicated compose files in `docker/`:

| File                                          | Use when                                                                  |
| --------------------------------------------- | ------------------------------------------------------------------------- |
| `docker-compose.prod-full.yml` (recommended)  | Single-server deployment — bundles PostgreSQL, with optional Neo4j        |
| `docker-compose.prod.yml`                     | You bring your own PostgreSQL (RDS, Cloud SQL, an existing server)        |

Released images are published as `ghcr.io/alfredo1996/neoboard`. Until a release is out, add `--build` so compose builds the image from your checkout; after that, drop it and pin a release with `NEOBOARD_IMAGE=ghcr.io/alfredo1996/neoboard:X.Y.Z`. Hosts with no internet access? [Air-gapped install](/deploy/air-gapped) lists what to mirror and what still needs a network.

### 1. Generate secrets

From the root of the clone:

```bash
# Generate the secrets ONCE, into a gitignored file. noclobber refuses to
# overwrite it: a new ENCRYPTION_KEY makes stored credentials unrecoverable.
(set -o noclobber; umask 077; cat > docker/.env.production.local <<EOF
POSTGRES_PASSWORD=$(openssl rand -hex 16)
ENCRYPTION_KEY=$(openssl rand -hex 32)
NEXTAUTH_SECRET=$(openssl rand -base64 32)
API_KEY_HMAC_SECRET=$(openssl rand -hex 32)
ADMIN_BOOTSTRAP_TOKEN=$(openssl rand -hex 32)
NEO4J_PASSWORD=$(openssl rand -hex 16)
NEXTAUTH_URL=https://neoboard.example.com
EOF
)
```

Set `NEXTAUTH_URL` in the file to the public URL users hit. Every compose command below reads the file with `--env-file`; the compose files **refuse to boot** when a required secret is missing — they will not fall back to insecure defaults.

:::caution
Losing `ENCRYPTION_KEY` makes every stored connection credential unrecoverable. Back up `docker/.env.production.local` with the same care as the database itself — see [Backup & Restore](/deploy/backup-restore).
:::

### 2. Start the stack

```bash
docker compose --env-file docker/.env.production.local -f docker/docker-compose.prod-full.yml up -d --build
```

To also run the optional bundled Neo4j data source:

```bash
docker compose --env-file docker/.env.production.local -f docker/docker-compose.prod-full.yml --profile neo4j up -d --build
```

Connect to it from NeoBoard with the URI `neo4j://neo4j:7687`.

### 3. Create the first admin

Two paths:

- **Bootstrap token** (recommended for production): step 1 already wrote `ADMIN_BOOTSTRAP_TOKEN`. Read it with `grep ADMIN_BOOTSTRAP_TOKEN docker/.env.production.local` and use it on the `/signup` page.
- **Bootstrap admin env vars** (dev/demo convenience): set `BOOTSTRAP_ADMIN_EMAIL` and `BOOTSTRAP_ADMIN_PASSWORD` before first boot and the admin account is created automatically.

### 4. Verify

```bash
curl -fsS http://localhost:3000/api/health        # status "ok"
docker compose --env-file docker/.env.production.local -f docker/docker-compose.prod-full.yml ps   # services "healthy"
```

`/api/health` is also what your uptime probe should hit — see [Monitoring](/deploy/monitoring).

### 5. Put it behind TLS

The HTTPS redirect is **on by default** in production. Terminate TLS at your reverse proxy ([nginx, Caddy and Traefik examples](/deploy/reverse-proxy)) and make sure it forwards `X-Forwarded-Proto`; set `FORCE_HTTPS=false` only if it cannot.

When the proxy sends `X-Forwarded-Proto: https`, or `NEXTAUTH_URL` is an `https://` URL, Auth.js names the session cookie `__Secure-authjs.session-token`, and the request proxy reads the session under that same name.

Then work through the [Deployment Checklist](/deploy/deployment-checklist) — resource limits, log rotation, backups, and monitoring — before going live.
