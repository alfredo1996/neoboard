The **Model** page shows what each of your connections holds, in words your team uses. For every connection you can give each thing a display name and a description, or hide it.

You do not type the structure in. It comes from the connector: the connection reports what it holds, and the Model page lays your words over it. A graph database reports things like node labels and relationship types. A SQL database reports tables and columns. If a connector reports no structure, its section says "This connection doesn't describe its structure."

## What you see

Each connection has its own section with three kinds of **term**:

- **Entities**, such as a node label or a table.
- **Relationships**, such as a relationship type or a link between tables.
- **Properties**, which belong to an entity or a relationship, such as a column.

Every term has a **Display name**, a **Description** and a **Hidden** switch.

## Who can see it and who can edit it

- **Anyone who can use a connection can read its terms.** That is the connection's owner, anyone in the tenant once the connection is shared, and admins.
- **Creators and admins can edit.** Readers see the same page with read-only fields. They do not get the Import or New concept buttons.

The server checks this too, so the page is not the only guard. See [Roles & Permissions](/security/roles).

## Describe a term

Click into a **Display name** or **Description** field and type. It saves when you click away.

- A display name can have up to **200 characters**.
- A description can have up to **2,000 characters**.
- One save can carry up to **1,000 terms**. You only meet this limit through the API; the page saves one term at a time.

Clear a field to take your words away. A term with no name, no description and no Hidden flag is not stored at all.

## Hide a term

Switch **Hidden** on for a term nobody needs, such as an internal column. The Model page stops listing it. Turn on **Show hidden** in the connection's section to see hidden terms again; they show greyed out with a **Hidden** tag.

Hiding an entity hides its properties from the list too. A hidden term is also left out of the query editor's autocomplete, the concept pickers and the concept hint. Hiding does not stop anyone from querying the term.

## Terms the database no longer has

If you described a term and the connection later stops reporting it, it stays in the list, crossed out and tagged **Orphaned**. Your words are kept in case the term comes back. You cannot edit an orphaned term. Click **Remove** on its row to delete your words for it.

## Refresh the structure

NeoBoard keeps a copy of each connection's structure for up to five minutes, so the page stays quick. A change in the database can take that long to show. To see it sooner, click **Refresh** in the connection's section.

- For **creators and admins**, Refresh reads the database again.
- For **readers**, the button reloads the copy NeoBoard already holds and does not read the database again. If a new table or label is missing, ask a creator or admin to refresh, or wait for the copy to expire.

## Find your way around a long model

- **Connections start closed.** Click a connection's name to open it. If you have only one connection, it opens by itself.
- **Entities start closed.** Click the arrow beside an entity to show its properties.
- **Search** looks through term names, display names and descriptions, and through concepts. It opens the connections that match.
  - It opens the matching entities too, but only while a connection has **20 matches or fewer**. With more, you see the count and open entities yourself.
- On the **Connections** page, the **Model** link under a connection jumps to its section here, already open.

## Export and import

Use **Export** and **Import** at the top of the page to move your descriptions and [concepts](/using/concepts) between installs, for example from a test setup to production.

### Export

**Export** downloads one file, `neoboard-model.json`. Anyone who can open the Model page can export.

It holds:

- the display names, descriptions and Hidden flags you set, for every connection you can use;
- your concepts, with only their sides on connections you can use.

It never holds a connection's structure or settings, a credential, or any internal account ids.

### Import

**Import** is for creators and admins. It works in steps:

1. Pick a `.json` file. It must be a NeoBoard model file, no larger than 10 MB. A file from a newer NeoBoard than yours is refused.
2. **Pair each connection** in the file with one of yours. A connection whose name matches one of yours is paired with it. Any other starts with **Skip** ticked; untick it to choose a connection. You can only pair connections you can use.
3. Click **Preview**. Nothing is saved yet. You see how many items are new, changed, no longer in the database, or skipped, and a name for each.
4. Click **Confirm** to save, or **Back** to change the pairing.

What an import changes:

- **The file wins for what it holds.** A term or concept in the file overwrites yours. It is a merge, not a replace: **nothing that is missing from the file is deleted.**
- A term in the file with no name, no description and no Hidden flag changes nothing.
- A term the database no longer has is still saved, and listed as no longer in the database (orphaned).
- Concepts are matched to yours by name or parameter, and their sides are added. Sides you already have are kept.
- A concept is skipped, and listed under **Skipped**, when none of its sides is on a connection you paired, when its name and its parameter match two different concepts of yours, when the match is a concept with no side on a connection you can use, or when a second concept in the file matches the same concept of yours.
