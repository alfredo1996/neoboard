Connectors are the bridge between NeoBoard and your databases. Each connector stores encrypted credentials and manages a connection pool.

## Supported Databases

| Database | Protocol | Query Language |
|----------|----------|---------------|
| Neo4j | `bolt://`, `bolt+s://`, `bolt+ssc://`, `neo4j://`, `neo4j+s://`, `neo4j+ssc://` | Cypher |
| PostgreSQL | `postgresql://`, `postgres://` | SQL |

## Setting Up a Connection

1. Go to **Connections** in the sidebar
2. Click **Add Connection**
3. Fill in the form fields:

| Field | Description | Example |
|-------|-------------|---------|
| Name | A label you will see in dropdowns | `Movie Database` |
| Type | Neo4j or PostgreSQL | `Neo4j` |
| URI | Database connection string | `bolt://localhost:7687` |
| Username | Database user | `neo4j` |
| Password | Database password | `password` |

4. Optionally, click **Test Connection** to verify connectivity
5. Click **Create**

## Connection Lifecycle

1. **Create** — you provide URI, username, and password
2. **Encrypt** — credentials are encrypted with AES-256-GCM before storage
3. **Test** — NeoBoard checks connectivity automatically right after you click **Create**, and you can check first with **Test Connection** in the dialog. Saving doesn't wait for the check: an unreachable connection is still saved and shows an **Error** badge. You can re-run the check later from the connection card. Opening the **Connections** page tests nothing: a connection shows **Not checked** until you run **Test Connection** from its card or **Test all**, which checks the connections you can test three at a time.
4. **Pool** — a connection pool is created on first query
5. **Cache** — the pool is reused for subsequent queries to the same database

## Credential Security

- Credentials are encrypted at rest with AES-256-GCM, using `ENCRYPTION_KEY` (32 bytes, hex) directly as the key; each value gets a random IV and is stored as `iv:authTag:ciphertext`
- Plaintext credentials are never logged or stored
- If `ENCRYPTION_KEY` is lost, all stored credentials become unrecoverable

## Advanced Settings

Each connector declares its own advanced settings — the key each is stored under, its unit and its valid range — so the table below is per connector. Timeouts are in milliseconds and accept 1000–300000; Max Pool Size accepts 1–100. A field left blank is not stored, and the default shown applies.

| Setting | `config` key | Applies to | Description | Default |
|---------|--------------|------------|-------------|---------|
| Connection Timeout (ms) | `connectionTimeout` | Neo4j / PostgreSQL | Time to establish a connection | 30000 / 10000 |
| Query Timeout (ms) | `queryTimeout` | Neo4j | Maximum query execution time | 30000 |
| Statement Timeout (ms) | `statementTimeout` | PostgreSQL | Statement timeout for queries, introspection and health checks | 30000 |
| Max Pool Size | `maxPoolSize` | Neo4j / PostgreSQL | Maximum concurrent connections (1-100) | 100 / 10 |
| Acquisition Timeout (ms) | `connectionAcquisitionTimeout` | Neo4j | Time to wait for a free pooled connection | Connection Timeout + 5000 (35000) |
| Idle Timeout (ms) | `idleTimeout` | PostgreSQL | Time before idle connections close | 10000 |
| Reject Unauthorized SSL | `sslRejectUnauthorized` | PostgreSQL | Verify the server's TLS certificate. On: encrypt and verify. Off, once the toggle has been changed: encrypt without verifying, whatever the URI says | Unset (the toggle starts off and is not saved until you change it): follows the URI's `sslmode`. `disable` means no TLS, `allow`/`prefer`/`require` encrypt without verifying, `verify-ca`/`verify-full` verify. With no `sslmode`, no TLS unless the server's `PGSSLMODE` environment variable says otherwise |

Each connector reads only the timeout it declares: Neo4j never looks at `statementTimeout`, and PostgreSQL never looks at `queryTimeout`.

**Max Rows per Query** (`maxRows`, 100–100000, default 5000) sits in the same panel but is NeoBoard's own row cap, not a connector setting: it applies to every connector type alike.

For PostgreSQL, the **Database** field applies when the URI names no database; a database on the URI path (`postgresql://host:5432/sales`) wins.

## Schema Introspection

NeoBoard can read your database schema to help with query writing:

- **Neo4j** — node labels, relationship types, property keys
- **PostgreSQL** — tables, columns, data types
