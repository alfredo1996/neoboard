Parameters make dashboards interactive. A user picks a value from a dropdown, types into a text field, or selects a date — and every widget that references that parameter re-runs its query automatically.

## How It Works

1. You add a **parameter widget** to your dashboard (e.g., a dropdown)
2. The user selects a value
3. Other widgets reference the parameter with `$param_name` in their queries
4. When the value changes, dependent widgets refresh automatically

## The `$param_name` Syntax

Use `$param_name` anywhere in your query to reference a parameter value. NeoBoard replaces it safely using parameterized queries — values are never interpolated into the query string.

**Cypher (Neo4j):**

```cypher
MATCH (m:Movie)
WHERE m.year >= $param_start_year
  AND m.year <= $param_end_year
RETURN m.title, m.year
ORDER BY m.year
```

**SQL (PostgreSQL):**

```sql
SELECT title, year
FROM movies
WHERE year >= $param_start_year
  AND year <= $param_end_year
ORDER BY year;
```

The parameter name must match exactly. If your parameter widget is named `start_year`, reference it as `$param_start_year` (NeoBoard adds the `param_` prefix automatically).

## Parameter Types

| Type | Input control | Value produced | Use case |
|------|--------------|----------------|----------|
| Select | Dropdown | Single string | Filter by category (e.g., country, status) |
| Multi-select | Dropdown with **Allow multiple selections** ticked | Array of strings | Filter by several categories |
| Freetext | Free-text input | String | Search by name or keyword |
| Date | **Date Picker**, mode Single Date | ISO date string | Filter by a specific date |
| Date Range | **Date Picker**, mode Date Range | Start and end, as `$param_<name>_from` and `$param_<name>_to` | Filter a time window |
| Relative Date | **Date Picker**, mode Relative Date: presets such as Today or Last 7 days | Start and end, as `$param_<name>_from` and `$param_<name>_to` | Filter a rolling window |
| Number Range | Dual-handle slider with a min, max and step | Low and high, as `$param_<name>_min` and `$param_<name>_max` | Filter between two numbers |

## Seed Queries

For **Select** and **Multiselect** parameters, you write a seed query that populates the dropdown options. The seed query runs once when the dashboard loads.

**Example seed query (Cypher):**

```cypher
MATCH (c:Country)
RETURN DISTINCT c.name AS value
ORDER BY c.name
```

**Example seed query (SQL):**

```sql
SELECT DISTINCT country AS value
FROM customers
ORDER BY country;
```

Each row becomes a dropdown option. The option's value comes from a column named `value`, or else the first column. The text the user sees comes from a column named `label`, or else the second column, or else the value itself. A single column is enough. To set both, return the value first and the label second, for example `RETURN c.id AS value, c.name AS label`. The editor's Test Seed Query preview reads columns by position, so this order makes the preview match the dashboard.

## Where Parameter Values Come From

- **User input** — the user selects or types a value (default)
- **Seed query** — a query populates dropdown options
- **Default values** — initial values set during widget configuration
- **Click actions** — clicking a chart element sets a parameter value (configured in the widget's Advanced tab)
