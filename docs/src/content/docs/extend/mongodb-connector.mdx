This guide walks through building a complete MongoDB connector plugin for NeoBoard. By the end, you will have an example plugin that lets users connect to MongoDB and run queries. [Creating a Connector Plugin](/extend/new-connector-plugin) has the full contract a connector must meet.

## Prerequisites

- Node.js 22+
- A NeoBoard instance running locally (`npm run dev`)
- A MongoDB instance (local or Atlas)

## 1. Scaffold the Plugin

Create a new directory in the connection package:

```bash
mkdir -p connection/src/mongodb
```

## 2. Implement the Connection Module

The connection module handles query execution. Create `connection/src/mongodb/MongoConnectionModule.ts`:

```ts
import {
  ConnectionModule,
  ConnectorError,
  ConnectorErrorType,
  DEFAULT_CONNECTION_CONFIG,
  QueryStatus,
  collectUpToLimit,
  determineQueryStatus,
  type AuthConfig,
  type ConnectionConfig,
  type QueryCallback,
  type QueryParams,
} from "@neoboard/connector-sdk";
import { MongoClient, MongoServerError } from "mongodb";

export class MongoConnectionModule extends ConnectionModule {
  authModule = null as any; // Satisfies abstract property; MongoDB uses client directly
  private client: MongoClient;

  constructor(authConfig: AuthConfig) {
    super();
    this.client = new MongoClient(authConfig.uri);
  }

  async runQuery<T>(
    queryParams: QueryParams,
    callbacks: QueryCallback<T>,
    config: ConnectionConfig,
  ): Promise<void> {
    try {
      await this.client.connect();
      const db = this.client.db(config.database);

      // Parse the query as a JSON command: { collection: "users", filter: {} }
      const command = JSON.parse(queryParams.query);
      const collection = db.collection(command.collection);

      // A falsy timeout means the default, not "no bound"
      const timeout = config.timeout || DEFAULT_CONNECTION_CONFIG.timeout;
      // maxTimeMS is enforced server-side
      const cursor = collection.find(command.filter ?? {}, { maxTimeMS: timeout });
      // MAX_ROWS+1: never a fixed row cap; keep config.rowLimit rows and detect one more
      const { rows: docs, truncated } = await collectUpToLimit(cursor, config.rowLimit);

      // Convert MongoDB documents to plain objects
      const rows = docs.map(({ _id, ...rest }) => ({ _id: String(_id), ...rest }));

      callbacks.setStatus?.(
        truncated
          ? QueryStatus.COMPLETE_TRUNCATED
          : determineQueryStatus(rows.length, config.rowLimit),
      );
      callbacks.onSuccess?.(rows as T);
    } catch (error) {
      if (error instanceof MongoServerError && error.code === 50) {
        // MaxTimeMSExpired
        callbacks.setStatus?.(QueryStatus.TIMED_OUT);
        callbacks.onFail?.(
          new ConnectorError(error.message, ConnectorErrorType.TIMEOUT, error),
        );
        return;
      }
      callbacks.onFail?.(error);
    }
  }

  async checkConnection(config: Record<string, unknown>): Promise<boolean> {
    try {
      await this.client.connect();
      await this.client.db(config.database as string).command({ ping: 1 });
      return true;
    } catch {
      return false;
    }
  }

  async close(): Promise<void> {
    await this.client.close();
  }
}
```

## 3. Create the Plugin Definition

Create `connection/src/mongodb/plugin.ts`:

```ts
import type { ConnectorPlugin, AuthConfig } from "@neoboard/connector-sdk";
import { MongoConnectionModule } from "./MongoConnectionModule";

export const mongoPlugin: ConnectorPlugin = {
  type: "mongodb",
  label: "MongoDB",
  category: "database",
  queryLanguage: "json",
  // find() does not enforce config.accessMode "READ". Keep this false, or
  // enforce READ with a read-only database user or role.
  supportsWrite: false,
  supportsGraphData: false,
  allowedProtocols: ["mongodb:", "mongodb+srv:"],
  uriPlaceholder: "mongodb://localhost:27017",
  databasePlaceholder: "mydb",

  createModule(authConfig: AuthConfig) {
    return new MongoConnectionModule(authConfig);
  },

  formFields: [
    {
      key: "uri",
      label: "Connection URI",
      type: "text",
      required: true,
      placeholder: "mongodb://localhost:27017",
    },
    {
      key: "database",
      label: "Database",
      type: "text",
      required: true,
      placeholder: "mydb",
    },
    {
      key: "username",
      label: "Username",
      type: "text",
      required: false,
    },
    {
      key: "password",
      label: "Password",
      type: "password",
      required: false,
    },
  ],
};
```

## 4. Register the Plugin

Add it to the connector registry in `connection/src/connector-registry.ts`:

```ts
import { mongoPlugin } from "./mongodb/plugin";

// After existing registrations:
registry.register(mongoPlugin);
```

Or, for a plugin shipped as its own npm package: install it into the NeoBoard checkout (`npm install neoboard-plugin-mongodb`), add `{ "package": "neoboard-plugin-mongodb", "export": "mongoPlugin" }` to the `connectors` array in `neoboard-connectors.json` (omit `export` if the plugin is the package's default export; add `"overrides": true` only to replace a connector with the same `type`, since a duplicate type otherwise throws at startup), then run `npm run dev` or `npm run build`. Both run `scripts/generate-connector-imports.mjs`, which compiles the package into the registry. Connectors are not discovered at runtime. See [Creating a Connector Plugin](/extend/new-connector-plugin#7-load-it-into-neoboard).

## 5. Install the MongoDB Driver

```bash
npm install mongodb --workspace=connection
```

## 6. Test the Plugin

Create `connection/__tests__/mongodb/` with integration tests using Testcontainers:

```ts
import { MongoDBContainer } from "@testcontainers/mongodb";

describe("MongoDB connector", () => {
  let container;

  beforeAll(async () => {
    container = await new MongoDBContainer("mongo:7").start();
  });

  afterAll(async () => {
    await container.stop();
  });

  it("executes a find query", async () => {
    const module = mongoPlugin.createModule({
      uri: container.getConnectionString(),
      username: "",
      password: "",
      authType: 1,
    });

    // Insert test data, then query
    // ...
  });
});
```

## 7. Use It

Once your connector is registered, the connection dialog still offers only Neo4j and PostgreSQL, so create the connection through `POST /api/connections` with `{ "name": "...", "type": "mongodb", "config": { "uri": "mongodb://host:27017", "database": "mydb", "username": "...", "password": "..." } }`. The API requires a non-empty `username` and `password` even if your MongoDB has no auth, so pass placeholder values your module ignores.

After that, testing the connection, listing databases and running queries all use your module. Queries are JSON, for example `{ "collection": "users", "filter": { "age": { "$gt": 25 } } }`. For now the widget editor offers only the table chart for a non-built-in connector type, the query editor is plain text, and widget templates cannot target it.

## Publishing as an npm Package

To distribute your plugin:

1. Create a separate package: `neoboard-plugin-mongodb`
2. Export the plugin definition
3. Users install with `npm install neoboard-plugin-mongodb`
4. List it in their `neoboard-connectors.json` (with `"export": "mongoPlugin"` for a named export) and rebuild with `npm run build`

[Creating a Connector Plugin](/extend/new-connector-plugin#7-load-it-into-neoboard) also explains that a Docker image built with `npm ci` can include the connector only once the package is published to a registry.
