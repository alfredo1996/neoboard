This guide covers adding a new interactive parameter type to NeoBoard.

## Overview

A parameter type requires:
1. Add to the `ParameterType` union
2. Handle in the parameter store
3. Create the widget component
4. Display the value
5. Wire into the renderer

## Step 1: Define the Type

Add your type to the parameter type union:

```typescript
export type ParameterType =
  | "text"
  | "select"
  | "multi-select"
  | "date"
  | "date-range"
  | "date-relative"
  | "number-range"
  | "cascading-select"
  | "your-type"; // Add here
```

## Step 2: Update Parameter Store

In `app/src/stores/parameter-store.ts`, handle your type's default value and coercion:

```typescript
case "your-type":
  return coerceYourType(rawValue);
```

The store manages parameter state, persistence, and cross-widget dependencies.

## Step 3: Create Widget Component

In `component/src/components/composed/parameter-widgets/`:

```typescript
export function YourTypeWidget({
  value,
  onChange,
  label,
  ...props
}: YourTypeWidgetProps) {
  return (
    // Your input UI
  );
}
```

**Boundary rule**: The component must be pure UI — no API calls, no stores.

## Step 4: Display the Value

`formatParameterValue` in `app/src/lib/parameter/format-parameter-value.ts` turns a parameter value into the text shown in the dashboard parameter bar. It chooses a format from the value's shape, not from the parameter type: strings (including relative-date presets), numbers, booleans, `[min, max]` number pairs, other arrays, and `{ from, to }` objects are already handled. Add a branch only if your type stores a value shape that isn't on that list. Add a matching case in `__tests__/format-parameter-value.test.ts`.

This function has nothing to do with queries. Parameter values never enter query text. Neo4j binds `$param_xxx` natively. For PostgreSQL, `rewriteParamsForPostgres` swaps the placeholders for positional `$1, $2, …` and sends the values separately. Any shaping your type needs before it reaches a query belongs in the store's coercion (Step 2), never in string formatting.

## Step 5: Wire into Renderer

Update `app/src/components/parameter-widget-renderer.tsx` to render your widget type.

## Step 6: Write Tests

1. **Store test** — verify coercion and state management
2. **Component test** — render with mock props (in `component/`)
3. **E2E test** — add parameter widget to a dashboard and verify it filters data
