Every NeoBoard user is assigned one of three roles. Roles determine what a user can see and do across the application.

## Role Comparison

| Capability | Admin | Creator | Reader |
|-----------|-------|---------|--------|
| View dashboards | Yes | Yes | Yes |
| Create/edit dashboards | Yes | Yes (own) | No |
| Delete dashboards | Yes | Yes (own) | No |
| Manage connections | Yes (create, edit and share their own; view and delete any in the tenant) | Own only (create, edit, test, delete) | No |
| Manage users | Yes | No | No |
| Access settings | Yes | Profile, API keys (create/revoke needs write permission) | Profile, view API keys |
| Run read queries | Yes | Yes | Limited (see Reader) |
| Run write queries | Yes (own connections; submit forms on any dashboard) | Yes (own connections, if enabled; submit forms on dashboards they can open) | Submit forms on dashboards they can open |
| Add or change forms | Yes (any connection) | Yes (connections they own or that are shared with the tenant, if enabled) | No |

## Admin

Full access to dashboards, user management, and settings. Admins are the only role that can create other users. Admins can see and delete every connection in the tenant, but can edit, or share tenant-wide, only connections they own.

## Creator

Can build and edit their own dashboards and widgets. Creators can add connections and edit, test, or delete the ones they own. They can also run queries against connections an admin has shared with the tenant, but cannot change or delete those. They cannot access user management. In Settings they can edit their profile and manage their own API keys; creating or revoking a key needs the write permission.

## Reader

Readers cannot edit dashboards, run write queries of their own, or add, change or delete connections. Like every user, they can submit the forms on dashboards they can open. They can see and run read-only queries against connections an admin has shared with the tenant, and against any connection they still own. On a dashboard shared with them as Editor, they can run any read-only query against that dashboard's connections. On a Viewer share or a public dashboard, they can only run the queries the dashboard already contains, each on the connection and database its widget uses.

Readers can open Settings to edit their profile and see their API keys, but cannot create or revoke keys.

## Write Permission

The **write permission** toggle is an additional control, independent of the role. When it is off, a Creator cannot run write queries of their own. They also cannot create, edit, duplicate, import or delete dashboards, manage widget templates, reassign connections, or create or revoke API keys. They can still view dashboards, run read queries, and submit forms on dashboards they can open, since a form does not need write permission.

| Role | Write Permission On | Write Permission Off |
|------|-------------------|---------------------|
| Admin | Can write (own connections) | Can write (own connections, always) |
| Creator | Can write (own connections) | View, read queries and form submits only |
| Reader | No effect | No effect |

Admins always have write permission regardless of the toggle. Outside forms, a write query only runs on a connection the user created; shared connections and connections owned by other users take none, even from admins. Forms work differently: anyone who can open a dashboard can submit its forms, whatever their role or write permission, and each submit runs only the query saved with the form, on the connection and database it is saved with. Adding a form, or changing a form's query, connection or database, needs access to that connection: its owner, anyone in the tenant once it is shared, or an admin. A form can therefore write through a tenant-shared connection its author does not own, and an admin's form through any connection. Turning the toggle off does not let a Creator build dashboards while blocking data changes; no setting does that today.

## Role Assignment

Admins assign a role when creating a user in **Users** management.
