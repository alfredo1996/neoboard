NeoBoard ships with built-in email/password authentication. No external identity provider is required.

## First Admin Setup

When NeoBoard starts with an empty database, the first account created on `/signup` becomes the **Admin**, provided it supplies the bootstrap token. This bootstrap flow:

1. Navigate to `/signup`
2. Enter the `ADMIN_BOOTSTRAP_TOKEN` from your environment in the bootstrap token field. Set it before first start (`neoboard` installs generate it and print it in the ready banner). First-admin signup is rejected without it.
3. Fill in your name, email, and password
4. Click **Create account**

You are now the first Admin and can create additional users.

Alternatively, for dev/demo only, set `BOOTSTRAP_ADMIN_EMAIL` and `BOOTSTRAP_ADMIN_PASSWORD` before first boot and the admin is created automatically, with no signup and no token (see [Production deployment](/deploy/production#3-create-the-first-admin)).

## Signing In

1. Navigate to `/login`
2. Enter your email and password
3. Click **Sign in**

Password login is always available, even when Enforce SSO is turned on for a provider or `OIDC_ENFORCE_SSO=true` is set. Neither setting blocks or hides the password form yet, and the login page does not show SSO buttons.

## Password Requirements

- Minimum 8 characters
- At least 1 letter
- At least 1 number

## Forced Password Change

Admins can require a user to change their password on next login by enabling **Force password change** when creating or editing a user. The user will be redirected to `/change-password` before they can access any dashboard.

## Session Management

- Sessions use JWT tokens (stateless)
- Default session duration: 8 hours (configurable via `SESSION_MAX_AGE`)
- Sessions are invalidated when:
  - A user's password is changed (with a 30-second grace period)
  - A user is disabled by an admin
  - An admin lowers a user's role on the Users page (with the same 30-second grace period). Other role and write-permission changes, including roles re-synced from SSO claims at sign-in, take effect in existing sessions without signing the user out.

## Rate Limiting

Login and signup attempts are rate-limited per client address:

- **20 login attempts** per minute
- **10 signup attempts** per minute

The address is the first `X-Forwarded-For` value. A client can set this header itself, so the limit only holds when your reverse proxy overwrites it with the real client address. With nginx, use `proxy_set_header X-Forwarded-For $remote_addr;` rather than `$proxy_add_x_forwarded_for`, which appends. Requests without that header share a single bucket, so run NeoBoard behind a proxy that sets it. For stronger protection, also rate-limit at the proxy.

Counters are kept in memory by each server process, so they reset on restart and are not shared between replicas. Both limits reset one minute after the first attempt in the window, and every attempt counts, successful ones included.

When login is rate-limited, the attempt fails exactly like a wrong password ("Invalid email or password"). When signup is rate-limited, the page shows "Too many signup attempts. Please try again later."

## Registration Control

Self-signup is **closed by default** since v1.0. The `/signup` page returns "Registration is currently disabled" unless you explicitly set `REGISTRATION_ENABLED=true`. Bootstrap of the first admin (with `ADMIN_BOOTSTRAP_TOKEN`) works regardless of this setting.

Existing users can still log in, and admins can still create users via the Users management page. Set `REGISTRATION_ENABLED=true` only for trusted dev/demo environments where open signup is acceptable.
