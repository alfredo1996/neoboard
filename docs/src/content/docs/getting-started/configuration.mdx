title: Configuration
description: Environment variables and configuration options for NeoBoard.
---

NeoBoard is configured through environment variables and an optional config file. Create a `.env.local` file in the `app/` directory (i.e. `app/.env.local`).

## Example `.env.local`

```bash
# Required
DATABASE_URL="postgresql://neoboard:neoboard@localhost:5432/neoboard"
NEXTAUTH_SECRET="your-random-secret-here"
ENCRYPTION_KEY="your-64-char-hex-key-here"

# Optional
NEXTAUTH_URL="http://localhost:3000"
SESSION_MAX_AGE=28800
```

Generate secrets with:

```bash
# NEXTAUTH_SECRET
openssl rand -hex 32

# ENCRYPTION_KEY
openssl rand -hex 32
```

Or use the CLI to generate everything automatically:

```bash
neoboard env generate
```

## Required Variables

| Variable | Description | Example |
|----------|-------------|---------|
| `DATABASE_URL` | PostgreSQL connection string for metadata | `postgresql://user:pass@localhost:5432/neoboard` |
| `NEXTAUTH_SECRET` | Secret for signing session tokens | Output of `openssl rand -base64 32` |
| `ENCRYPTION_KEY` | AES-256 key for encrypting stored credentials | Output of `openssl rand -hex 32` |

## Optional Variables

### Auth

| Variable | Description | Default |
|----------|-------------|---------|
| `NEXTAUTH_URL` | Public URL of the NeoBoard instance | `http://localhost:3000` |
| `TENANT_ID` | Multi-tenant isolation key | `default` |
| `SESSION_MAX_AGE` | Session timeout in seconds | `28800` (8 hours) |
| `REGISTRATION_ENABLED` | Allow new user signups | `true` |
| `ADMIN_BOOTSTRAP_TOKEN` | Token required for first admin signup | (unset) |
| `BOOTSTRAP_ADMIN_EMAIL` | Auto-create admin on first start | (unset) |
| `BOOTSTRAP_ADMIN_PASSWORD` | Password for auto-created admin | (unset) |
| `API_KEY_HMAC_SECRET` | HMAC key for API key hashing | (auto-generated) |

### Security

| Variable | Description | Default |
|----------|-------------|---------|
| `FORCE_HTTPS` | Redirect HTTP to HTTPS | `true` in production |
| `CORS_ALLOWED_ORIGINS` | Comma-separated allowed origins | `NEXTAUTH_URL` only |

## SSO / OIDC Variables

SSO requires `NEOBOARD_EDITION=enterprise`. Set the three required OIDC variables plus the edition flag to enable single sign-on. See the [SSO guide](/authentication/sso) for full setup instructions and IdP examples.

| Variable | Description | Default |
|----------|-------------|---------|
| `OIDC_ISSUER` | OIDC issuer URL | (required for SSO) |
| `OIDC_CLIENT_ID` | OIDC client identifier | (required for SSO) |
| `OIDC_CLIENT_SECRET` | OIDC client secret | (required for SSO) |
| `OIDC_DISPLAY_NAME` | Login button label | `SSO` |
| `OIDC_CLAIM_KEY` | IdP claim for role mapping | (unset — no mapping) |
| `OIDC_DEFAULT_ROLE` | Role when no claim matches | `creator` |
| `OIDC_ENFORCE_SSO` | Hide password form for non-admins | `false` |

## Enterprise Variables

Set `NEOBOARD_EDITION=enterprise` to enable enterprise features like the Admin UI for multi-provider SSO, custom roles, and more.

| Variable | Description | Default |
|----------|-------------|---------|
| `NEOBOARD_EDITION` | Set to `enterprise` to enable enterprise features | (unset — community edition) |

## Health Endpoint

NeoBoard validates all environment variables on startup and exposes a health check at:

```
GET /api/health
```

Returns `200` when config is valid, `503` when required variables are missing. Reports set/unset status per variable (never actual values). Useful for Docker health checks and monitoring.

## View Current Config

Use the CLI to inspect environment variable status:

```bash
neoboard env list
```

Or check project configuration (ports, database credentials):

```bash
neoboard config list
```

## Security Notes

- **`ENCRYPTION_KEY`** is critical. If lost, all stored database credentials become unrecoverable.
- Never commit `.env.local` to version control.
- Rotate `NEXTAUTH_SECRET` periodically in production.
